# 3D milestone 1: bounded deterministic material sandbox

The experimental `state-space-engine/experimental/3d` entry implements CPU
rules `ca-3d-m1`, snapshot schema 1, with the built-in catalog identity. It is
independent of the shipped 2D `ca-v4` rules. The browser viewer uses native
WebGPU for presentation and a dedicated CPU worker for physics.

**M1 passes its correctness gate.** All three scenes have exact Node/browser
continuation and zero energy drift. The measured 32³ full-frame baseline is
about 30–31 ticks/second on the recorded i9-11900K / RTX 4090 system; it does
not meet a 60 Hz frame deadline. Performance was diagnostic for this milestone.

## State and integration contract

Dimensions are positive integers with at most 32,768 cells in total. Odd,
rectangular and single-cell dimensions are supported. Storage is row-major
`x + width * (y + height * z)`; increasing Y points down. Boundaries are closed.
Each cell has a packed material/thermal/phase word and integer `energyQ`.
Kinetic and flag bits are zero; phase must equal the material's default phase.
Energy stays in the existing `[0, 0x3fffffff]` range. A complete volume sum is
below 2^45 and is exactly representable before conversion to BigInt.

Supported IDs are air, stone, sand, water, ice, steam, lava, glass and molten
glass. This set is closed under the existing phase transitions. Material
properties, thresholds, hysteresis, latent intervals and thermal exchange come
from the existing catalog and dimension-independent thermal implementation.
There is no custom registry argument in M1.

`createStateSpaceField3D(width, height, depth, fillMaterial?)` exposes read-only
dimensions/tick, isolated `grid`/`energyQ` copies, `step`, `sample`, `setCell`,
`setEnergy`, `copyStateInto`, `snapshot`, `restore`, `energyLedger` and
`energyBalance`. `step` accepts 0–1,024 ticks per call. `copyStateInto` requires
two nonoverlapping, owned Uint32Arrays of the complete cell count.

Snapshots contain schema/rules/catalog identity, dimensions, completed absolute
tick, `packedCells` and `energyQ`. Both arrays are JSON-compatible number arrays.
Restoration requires identical field geometry and validates the entire input
before commit. 2D saves and unsupported state are rejected. Restore establishes
a fresh energy-accounting baseline; subsequent edits record their external
energy deltas. Snapshots resume physics; they do not contain a client edit log.

## Exact tick schedule

All passes read immutable input and write a separate output. Movement swaps
both coordinates; phase conversion leaves energy unchanged. Every pair pass
uses parity 0 before parity 1; unmatched boundary cells are copied.

1. Two vertical Y gravity passes. Powder and liquid/viscous/molten cells can
   displace lower-density, nonfixed cells below them.
2. Eight diagonal passes: downward offsets +X, −X, +Z, −Z, each with even/odd Y
   source rows. Rotate that four-direction list by `tick % 4`. Descent requires
   blocked straight descent and an eligible diagonal destination. These are
   cardinal horizontal offsets, not corner diagonals or a surface-tension law.
3. Four liquid spread passes: even/odd X and Z pairs, with axis order X/Z on
   even ticks and Z/X on odd ticks. Liquids spread into lower-density gas only
   when neither straight nor any of the four diagonal descents is available.
4. Two Y gas buoyancy passes. Non-air gas rises into gas when its rank exceeds
   the destination rank by more than 16. Rank is
   `2 * floor(temperatureQ/256) - density`.
5. Four lateral gas passes in the same X/Z axis order. A non-air source blocked
   from rising can spread into air, or into gas whose rank is lower by more
   than 16. Direction is chosen by the u32 hash below.
6. Six heat passes: X even/odd, Y even/odd, Z even/odd. Use the existing harmonic
   conductivity and exact equal-and-opposite integer exchange.
7. One phase-conversion pass using existing energy thresholds.

The lateral choice hash uses the lower pair index `i`, axis `a` (X=0, Z=2)
and low 32 bits of the absolute tick `t`:
`h = imul(i,374761393) + imul(a,668265263) + imul(t,1442695041)` modulo 2^32;
then `h = imul(h ^ (h >>> 13),1274126177)` modulo 2^32. A zero low bit of
`h ^ (h >>> 16)` chooses the lower endpoint as source; otherwise the higher.

There are 27 passes. A cell can move in multiple successive passes in a tick;
ticks and velocities are not SI quantities. Solids/frozen cells remain fixed
until edited or transformed, including ice formed in midair. This milestone
has no pressure, stored velocity, combustion, bonds, structural collapse,
rotation, momentum budget, sparse chunks or GPU physics. Exact conservation
covers sensible + latent + chemical energy, using the existing model units.

## Verification and performance

The acceptance gate is exact behavior and replay. A missed 60 Hz deadline is
reported, and does not fail this milestone. The viewer's opaque water,
directional lighting, steam markers and cutaway are diagnostic presentation;
the earlier 2D renderer's full effects stack is outside this milestone.

Build and open the viewer:

```powershell
npm ci
npm run build:sdk
uv run python -m http.server 8765 --bind 127.0.0.1
# Open http://127.0.0.1:8765/examples/volume-lab/
```

Reproduce verification and timings, in order, with background workloads paused
for the timing runs:

```powershell
npm run verify:3d
npm run benchmark:3d
uv run python -m scripts.verify_volume_browser --browser-cli <agent-browser-cli> --frames
```

The first command checks 1,024 ticks per scene, an identical repeated run, and
restarts at ticks 3 and 509. It retains full final arrays and tick-660 hashes
for benchmark comparisons. The browser command compares the worker's complete
state with Node, exercises controls, invalid operations and presentation
isolation, and runs the three sequential full-frame measurements. Its progress
journal is flushed to disk; cancellation/failure retains partial results.

Node timings include public `step` and its 27 passes. Browser timings additionally
include worker scheduling, transfer/counting/accounting, meshing, uploads, HUD
updates and native GPU completion at 1920×1080. Both retain 60 warmup samples
separately from 600 measured samples. Setup, state hashing and OS scanout are
excluded. These are CPU physics measurements with diagnostic 3D rendering;
there is no 3D GPU-physics parity claim.

The existing 16-stage verification suite passed: native tests and invariants,
TypeScript/Web tests, lint/type checks, both game builds/tests, packaged SDK
clients, hardware browser/native conformance and evaluation adversaries plus
benchmark. The final 3D reporting and client error-recovery changes were followed by
fresh 3D checks; the shared 2D runtime was unchanged.

### Recorded M1 results

Eight focused engine tests pass, alongside lint/type checks and the existing
16-stage suite. Each scene ran 1,024 ticks, an identical repeated run and two
independent split restarts at ticks 3 and 509. The browser worker matched both
complete arrays and metadata from Node, including those restart paths.
Presentation isolation, invalid imports/edits, recovery after uncloneable input
and exact external-edit accounting passed. A controlled renderer exception
also paused playback while retaining an exact snapshot that the export control
could still save.

The long correctness runs overlapped background encoding. Timing runs started
after those encodes finished: before timing, CPU load was 12%, GPU utilization
was 0%, and no FFmpeg processes remained. After timing, CPU/GPU utilization was
0%. The CPU and browser timing runs were sequential. See the
[before](volume-m1/benchmark-host.json) and
[after](volume-m1/benchmark-host-after.json) inventories for the recorded conditions.

| Scene | Node CPU median / p95 tick | Full-frame p95 work | Worst callback → GPU completion | Benchmark tick rate | Missed 16.67 ms deadlines |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sand & water | 11.90 / 13.30 ms | 22.3 ms | 55.6 ms | 31.23 Hz | 588 / 600 |
| Hot / cold chamber | 13.17 / 18.28 ms | 21.3 ms | 36.9 ms | 30.13 Hz | 600 / 600 |
| Rock / glass melting | 12.12 / 17.22 ms | 19.9 ms | 35.8 ms | 31.28 Hz | 600 / 600 |

Each full-frame scene completed 60 warmup plus 600 measured frames at
1920×1080. Frame samples contain one completed physics tick each; the achieved
rate describes that display-paced measurement loop. All three measured runs
ended at tick 660 and exactly matched the independent Node run, with zero
energy drift and no browser errors. Sources were unchanged during the runs.

Median browser worker turnaround was 11.1–11.8 ms and rendering/HUD work was
6.7–7.0 ms. Median complete work was 18.1–18.6 ms, exceeding the 16.67 ms budget
before display pacing adds any wait. These results establish the CPU reference
baseline, with GPU physics and further performance work deferred.
