# C5: trustworthy evolution and performance

Status: verified. The final full gate completed on 2026-09-07 at 22:34:39 UTC:
all 14 commands passed with unchanged source hashes. The sources and evaluation
context were compared again after completion and still matched. The earlier
pre-optimization gate and matrix remain in `c5-before-boundary-verification.json`
and `c5-before-boundary-benchmark.json`.

## Reproduced baseline defects

`c5-baseline.json` records exact counterexample source, old evaluator results,
source hashes, and the native NVIDIA RTX 4090/Vulkan adapter:

- A copy-only physics shader passed phases 2a, 2b, 2c, and 2d. Conserved counts and
  deterministic output did not require observable physical behavior.
- A shader with broken packing, unpacking, and exchange helpers passed by using
  its own identity-copy entry point.
- Thermal fitness with an invalid objective and a nonzero energy error was
  accepted; an empty fitness dictionary was considered viable.
- Historical archives supplied 50 eligible candidates across seven phases with
  no current code, contract, device, or evaluation-policy check.

The old runner also stopped physics timing after submission rather than explicit
GPU completion. Ranking and eviction used different objective conventions, and
the evaluated shader could be silently repaired while a different raw source was
written as the winner.

## Current implementation

`docs/EVOLUTION.md` documents the supported targets, local evaluation/search,
optional bounded paid proposal generation, staging, evidence, and measurements.

An immutable `ShaderBundle` captures every runtime shader before compilation.
The evaluator replaces exactly one production kernel and uses the real compositor,
storage adapter, complete energy state, catalog, and 34 pipeline variants.
Source changes during evaluation invalidate the result.

The independent TypeScript CPU implementation supplies complete pass references
for 29 deterministic scenes, including the earlier conformance corpus, four
cross-workgroup workloads, a custom material registry, high IDs, fractional
energy, and nonzero starting ticks. Acceptance compares 1,808 complete passes.
Every variant of the target must perform observable physics somewhere in that
corpus. Repetition and split/resume require exact final packed and energy arrays.

Phase-specific integer gates include exact energy conservation, material-count
preservation where identities must remain unchanged, complete CPU equivalence,
determinism, restart, positive behavior, and codec helper outputs. Objectives must
be finite, positive measurements. The codec harness independently constructs pack
inputs and observes every unpacked field; a candidate cannot supply the harness.

Candidate text, source/context bundles, input/reference scenes, shader bundles,
compiled shader hashes, logs, and reports are content-addressed. Shared input and
reference data are stored once. Context includes device/driver/backend, runtime
versions, the actual TypeScript compiler hash, catalog and rule sources, seeds,
and measurement configuration. Worker deadlines fail closed.

Archive admission and ranking require current receipts and internally consistent
evidence. Mutable candidate fitness is display-only and is discarded on import.
One Pareto-ranking implementation handles objective directions and deterministic
ties. Unqualified candidates cannot evict qualified parents. Staging performs a
fresh evaluation and emits exact source, base hash, and a reviewable patch;
search does not overwrite production winners.

The historical 1b/1c protocols are inactive ca-v1 experiments and cannot qualify as
current engine optimizations. Their source archives remain intact. The current
targets cover every active physics kernel as well as the codec.

## Targeted sweep and prevention

| Failure class | Executed check and prevention |
| --- | --- |
| Conservation-only no-op admission | Eight compiled no-op kernels, one per physical target, must fail observed GPU/CPU equivalence. Positive coverage includes every target variant. |
| Broken codec hidden by a copy entry | Actual GPU helper-field negative controls; the host owns entry points and storage. SS025 rejects candidate-owned bindings and invalid entry contracts. |
| Created thermal energy, shared oxygen, duplicate fuel release | Three compiled mutations must fail with recorded first differing cell/pass and exact budgets. Reaction identity changes are checked against the full independent reference. |
| Missing, non-finite, boolean, stale, or self-reported scores | Required-field/type properties; zero-case rejection; current receipt checks; altered-code/device/policy/seed/config and incomplete-report controls. SS026 prevents candidate fitness from authorizing ranking; SS028 requires finite JSON. |
| Different evaluated and staged code | Immutable source identity, captured shader inputs, fresh staging, and SS027 forbidding silent shader repair in the evaluation path. |
| Submit-only timing or invalid distributions | Queue-order property and invalid-sample controls; SS029 requires completion inside the timed interval; warmups and raw distributions are retained. |
| Runaway proposal work | Bounded proposal counts, worker deadlines, SS024 restrictions on loops/barriers, and SS030 subprocess deadline checks. These controls are not a hostile-code GPU sandbox. |
| Old archives contain non-standard Infinity values | The first C5 audit reproduced import failure. Explicit legacy-list import discards all scores/receipts and non-finite metadata while preserving source history; current artifacts retain strict JSON parsing. A regression covers both paths. `c5-archive-import-sweep.json` verifies 105 sources retained, zero eligible parents, and unchanged original files. |
| Aggregate timeout discards useful partial output | The first full gate passed 13 commands, then hit the old 180-second deadline. The combined bounded audit/matrix has a 600-second deadline; partial stdout/stderr and completed benchmark-row artifacts survive. A timeout property requires failed status and retained diagnostics. |
| SDK checks overwrite a fixed historical report/package path | SDK verification now accepts a per-run report path and preserves reports and package bytes under content hashes. Existing historical run records remain descriptions of their recorded source context; C5 starts immutable package preservation. |
| Large-grid native calls repeatedly run scalar cell validation/accounting | The baseline 512x512 matrix took roughly 1.6-1.7 seconds per four ticks despite roughly 2 ms synchronized tick times. `c5-boundary-profile.json` attributes the cost to more than two million scalar integer checks. Bulk signed-integer projections/accounting now retain complete validation and are checked against the unchanged scalar reference. |
| Vectorized arithmetic can wrap negative phase offsets or whole-world sums | Executed unsigned-intermediate and narrow-reduction mutants fail phase-boundary and greater-than-u32 ledger checks. SS031 requires signed 64-bit reductions; SS032 rejects narrow/unsigned/floating energy intermediates. Seeded full-range, threshold-neighbor, high-ID, malformed-input, alias, and no-scalar-fallback properties cover the optimized path. |
| Host wall-time scores can be moved between different CPUs sharing a GPU model | CPU identity, logical CPU count, and a hashed host identity now participate in context equality. A changed-host receipt must fail admission. |

The first aggregate report is `c5-verification-first.json`; it records the timeout
and unchanged source hashes. Failed-candidate receipts remain in
`c5-evaluation/evidence/` with their exact observed differences. No paid generation
or production-winner promotion is part of verification.

## Performance scope

The baseline matrix covers sparse, dense-flow, thermal, and reactive worlds at
32x32, 128x128, 257x129, and 512x512. Defaults are two discarded warmups and seven
measured four-tick runs, each beginning from the identical full state and tick.
Every repetition must return the same complete result and conserve all energy.

Reported timing is synchronized host wall time. Tick samples include command
encoding, submission, and completion. End-to-end samples also include validation,
allocation, uploads, and full-state readback. Compilation, registry construction,
scene generation, reference evaluation, and report writing are excluded. Raw
samples and distribution summaries are preserved. These measurements establish a
native baseline on the recorded device; they do not establish browser throughput,
universal cross-device parity. The preserved pre-optimization matrix provides the
same workloads for the final host-boundary performance comparison.

## Verified performance result

`c5-performance-comparison.json` links immutable before/after receipts. All 16
workloads have identical initial state, final packed/energy state hashes, energy
totals, dimensions, seeds, starting ticks, warmups, and sample counts. The GPU and
previously recorded runtime properties match. Intended differences are the
optimized host implementation and additional host provenance.

Final 512x512 median end-to-end time per four-tick call:

| Workload | Before | After | Improvement |
| --- | ---: | ---: | ---: |
| Sparse | 1,616.16 ms | 72.70 ms | 22.23x |
| Dense flow | 1,699.37 ms | 63.11 ms | 26.93x |
| Thermal | 1,716.04 ms | 62.78 ms | 27.34x |
| Reactive | 1,684.70 ms | 65.21 ms | 25.84x |

This is a measured native host-boundary improvement on the recorded machine.
GPU kernels, physical rules, public state semantics, and full validation remain
unchanged. Sampling variation is visible in the stored distributions; an earlier
post-optimization run measured 24-31x on these workloads. No browser performance
improvement is inferred from the native results.

The unsigned-intermediate negative control incorrectly projects zero-energy steam
as 23040 Q of temperature instead of zero. The narrow-sum control reports
4294967288 Q instead of 8589934584 Q for eight high-energy cells.
`c5-bulk-sweep.json` preserves both actual observations and the tested source hash.
