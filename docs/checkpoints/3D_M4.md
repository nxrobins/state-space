## Exact skipping contract

An activity tile may sleep only if a conservative predicate proves every cell is unchanged
under every possible pass and gas tie-break. The predicate checks both directions
of all possible gravity/diagonal, liquid and gas exchanges, phase destinations,
thermal normalization and the exact integer exchange across every heat edge. It ignores
some blocking conditions, so it can retain unnecessary work but cannot remove a
possible write. Unequal temperatures can sleep only when the actual capped integer
exchange is zero. One unchanged tick is never used as a sleep certificate.

The largest read stencil in the frozen law has Chebyshev radius two (a horizontal
pair's blocked-descent probe). Every changed cell and every external edit wakes
all activity tiles intersecting that radius before the next pass. One planner
rebuilds the canonical list at the beginning of a tick when membership changed.
Within the tick, an atomic 0-to-1 wake claims one new list slot. Existing entries
never move: the dispatch dimensions freeze the current pass's prefix while new
entries are appended for its successor. Append order may vary, but each tile
occurs once, each invocation owns one output cell, and all pair decisions read
immutable input coordinates. Ownership, hashing and tie-breaking use global
coordinates and absolute tick, never list position or visibility.

At each tick boundary, all awake tiles, including final-phase wakes, are
certified against the committed state. Their cells and energies are copied to
the spare bank in a separate dispatch from physics. Only then can a tile sleep;
both banks agree for every skipped cell. Creation initializes both banks and
certifies initial activity. Restore initializes both banks and conservatively
wakes all tiles. Activity is derived metadata absent from portable snapshots.

Two indirect-argument buffers alternate with the state banks. A physics dispatch
reads one argument buffer and atomically grows the other for its successor; it
never binds its own indirect input as writable storage. Atomic maximum preserves
the current count even without new wakes. Canonical compaction resets both counts
at the next tick. The active geometry accepts
complete power-of-two chunks of edge 4–32, dimensions through 128 and at most
512 storage chunks. Activity tile edge is `min(chunkSize,8)`: the default 128³
world has 64 storage chunks and 4,096 activity tiles. The new envelope is
`finite-active-1`. Mechanical state, pressure, combustion and streaming remain
outside this milestone; stone, glass and ice remain fixed until edited or transformed.

### Kernel arithmetic follow-up

GPU field dimensions are now compile-time constants. They cannot change over
the field's lifetime, so address arithmetic can simplify power-of-two divisions
without changing global coordinates, pair ownership, pass order or the uniform
ABI. Odd rectangular dimensions use the same exact mapping and are covered by
the individual-pass comparisons.

Heat passes skip equal-material, equal-energy pairs, matching the CPU reference's
existing no-op. Validated states have normalized thermal bits; movement preserves
them, and edits, heat exchange and phase changes regenerate them. Equal material
and energy therefore imply equal exact temperature and zero exchange. Sparse
certification uses the same shortcut before calculating a neighbor temperature;
its own normalization, phase and all movement/heat checks still apply.

The earlier kernel-only follow-up measured a 128³ full-frame median of **9.9 ms**,
versus **10.4 ms** immediately before that work (about 5% lower). Physics/query median is 6.4 versus 6.8 ms;
completion p95 is 12.0 versus 12.2 ms. The smaller worlds remain within the
60 Hz gate, but their timings are higher than the preceding runs; this is not
evidence of a speedup at 32³ or 64³.

That earlier follow-up's retained `timing128-abfbd535` GPU-timestamp run reports median physics/planning/certification
of **3.801088 ms**, versus **4.194304 ms** in the earlier GPU diagnostic (about
9% lower). Its p95 is 4.456448 versus 4.587520 ms. These are separate sequential

### Deadline-miss diagnosis and allocation fix

The [Chrome trace diagnosis](volume-m4/safety/gc-diagnosis.json) binds a missed
frame to renderer-thread garbage collection: an 8.107 ms major collection,
followed by 5.311 ms of native-wrapper sweeping. Heap use fell from 110,575,800
bytes to 37,959,952 bytes. These tasks delayed asynchronous GPU completion
callbacks. The GPU-only timing could not explain the stall: a preceding diagnostic
captured roughly 0.07 ms of mesh/draw work inside a 12.2 ms render-completion wait.
The full Chrome trace is retained compressed in the diagnostic run evidence.
Tracing itself can perturb timing; the passing frame gates have tracing disabled.
This identifies the traced frame's cause, not the earlier workstation freeze.

The cavern's initialize/restore path now sums energy directly across chunks,
without flattening 2,097,152 entries or creating a BigInt per voxel. The total is
bounded by `128³ * (2³⁰ - 1) < 2⁵¹`, so integer Number addition is exact; conversion
to the public BigInt ledger happens once. A maximum-total regression verifies
this bound. Game snapshot validation reuses its first validated flat state for
the actor-overlap test instead of flattening and validating the world twice.
Public snapshot ownership, whole-input validation and atomic imports remain intact.
A fresh complete CPU reference replay proves compatibility with the original
fixtures, and both GPU modes and odd-tick restarts match that reference.

Other retained reductions remove redundant work:

- The original implementation rebuilt/reused a canonical activity list before
  each pass. The current append scheduler compacts once per tick and preserves
  an immutable prefix within each dispatch. Final wakes are included in the
  end-of-tick certificate. The probe intercepts actual API calls and verifies
  three planner dispatches over three ticks, with 81 total build/reuse decisions.
- Fixed solids skip movement-only checks, including in the sleep predicate.
  Their heat exchange, thermal normalization and phase transitions still run.
- Ordinary sparse ticks use GPU buffer clears for activity counters/reasons,
  eliminating a 16 KiB zero-array allocation and upload plus the small counter
  upload. Only 7,424 parameter bytes upload on an ordinary tick. Edit ticks reuse
  zero storage and preserve external wake reasons; dedicated GPU regressions
  compare complete states and assert upload volume and edit reason retention.
- Benchmarks push bounded UI progress over local HTTP, with one request in
  flight, instead of spawning CLI/CDP polls during measurement. The unchanged
  15-second stall detector still requires actual progress. Removing polling alone
  did not fix the miss; that failed run is retained.

Planner-only, fixed-solid, observer and GPU-clear attempts all retained deadline
misses. The final setup-allocation cleanup passed on its first untraced full-frame
run (`frames128-1ed02ba6`). No forced garbage collection, artificial settling delay,

## Safe verification

All recovery jobs use the OS lease and contained process-tree supervisor.
Tiny probes precede 64³ conformance, which precedes any 128³ execution. Every
correctness tick is awaited and yields; a GPU tick over 100 ms aborts verification.
Benchmarks run sequentially in fresh sessions and retain raw frames. CPU jobs
have a 6% aggregate CPU cap and 4 GiB job memory limit; GPU correctness uses 12%
CPU and 8 GiB. Frame measurements use normal priority without a CPU rate cap.
Every run first requires available system/GPU memory, CPU below 50%, GPU load at
most 15%, and GPU temperature below 65°C. Per-second host/job telemetry and
two-second GPU telemetry stop runs on low memory, GPU temperature at 75°C,
lost GPU telemetry, or sustained host CPU above 85%. Progress and overall
deadlines, cancellation and the 2-second monitor-lag limit remain active.

The earlier successful frame runs peaked at 39°C GPU temperature and about 1.59 GiB
process-tree memory. These observations describe recovery runs, not conditions
before the freeze. Fourteen isolated supervisor tests cover containment, exclusion,
descendant cleanup, hold/permit behavior, health thresholds and stale GPU-proof
rejection before any child can launch. Host readings are
stubbed for the print/sleep containment fixtures so background load cannot turn
those unit tests into a false failure; real runs use actual telemetry.

No software watchdog can guarantee recovery from a kernel/hardware stall.
The precise original cause remains unresolved. The legacy workload remains
quarantined, and the full `engine.verify` gate explicitly retains that failing
requirement instead of treating the smaller default unit suite as full coverage.

Controlled recovery uses `python -m scripts.recover_m4_verification <stage>`.
The ordered runtime stages are `cpu-smoke`, `unit`, `probe`, `gate64`, `frames32`,
`frames64`, `continuation128`, `frames128`, `ui`; browser stages require
`--browser-cli <path>`.
`receipt-tests`, `lint`, `typecheck`, `build`, `sdk` and `publish` are separate bounded stages.
`cpu-reference` is a CPU-capped, 600-second maximum compatibility replay against
the original complete fixtures. `diagnostic128` adds GPU timestamps and a bounded
Chrome profile; its performance result is diagnostic and does not replace the

Previous stages must pass before advancing; relevant GPU source hashes must
