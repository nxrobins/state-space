# C4: embedding and extension — verified

The 0.2 SDK provides native Python, browser/Node CPU, and browser WebGPU fields
through public entry points. Runtime assets are packaged, material registries
are immutable and validated, snapshots use registry identity, and optional pass
reports expose complete cell and energy changes. `docs/SDK.md` documents APIs,
compatibility, lifetime, numeric conventions, examples, and current costs.

## Baseline and targeted sweep

`c4-baseline.json` records the installed-wheel failure and original source hashes.
The wheel built and installed successfully but contained no runtime winners;
creating a compositor outside the checkout failed looking for `site/locked`.
The same baseline confirmed that version-2 material ID 15 could be renamed,
snapshot array writeability could be re-enabled, and the TypeScript factory
accepted only literal air (0) as its fill argument.

| Finding | Correction and automated prevention |
| --- | --- |
| Installed wheel depends on checkout kernels | Generated package assets plus package-relative resource access. SS001 checks packaged copies; SS017 rejects runtime checkout roots; SS018 prevents runtime generator imports. Actual installed clients are mandatory gates. |
| Catalog extensions can reuse version-2 identities | Python and TypeScript preserve all IDs 0-17. Catalog-wide identity rejection properties and shared JSON validation cases cover this boundary. |
| Frozen Python snapshots expose writable owning arrays | Snapshots now use immutable bytes-backed arrays. A property attempts to re-enable writeability on both arrays and must fail. |
| Registry aliases or asynchronous caller mutation can change authority | Registries clone inputs before hashing, freeze exposed records, and return independent catalog/cold-table copies. Alias, mutation-race, and cross-language hash properties enforce this. Generated browser definition objects are deeply frozen. |
| Inferred fill type rejects non-air clients | Explicit numeric parameter types; SS020 with positive/negative controls. Actual external TypeScript clients compile with both installed compiler versions under NodeNext. SS021 requires portable relative ESM import extensions. |
| Buffer cleanup is not deterministic after partial run setup | Every run buffer registers with an ExitStack. An injected bind-group failure verifies destruction of all five real buffers; SS019 rejects unowned allocations and removal of the cleanup scope. |
| Failed recompilation destroys a previously usable cache | `c4-compile-cache-sweep.json` reproduces an old-dimension tag with zero pipelines, followed by `KeyError: vertical0`. New caches commit only after successful compilation. An injected compiler failure must preserve and run the previous world; SS022 prevents incremental live-cache mutation. |
| Inspection can silently truncate one half of a trace | Both trace arrays must contain the complete schedule in order. Removing a pass in an injected result must fail without committing field state. |
| Clear can partially replace state if the second allocation fails | Both arrays allocate before commitment. An injected second-allocation failure must preserve snapshot and accounting. |
| Browser and native sampling disagree beyond the safe numeric range | A TypeScript regression first demonstrated acceptance of `Number.MAX_VALUE`; both APIs now reject out-of-range sample geometry. Shared boundary properties enforce this. |
| Null serialized catalog hash is silently inferred | Reproduced through `Snapshot.from_dict`; transport now requires an explicit string hash. Null, wrong, and altered-registry snapshots must be rejected atomically. Constructor convenience does not weaken transport validation. |
| Browser example never starts under the Windows static server | The `.mjs` response had Content-Type text/plain. The entry now uses `.js`; SS023 rejects `.mjs` HTML entry paths. Actual browser verification requires a rendered, initialized field and positive behavior, not just empty console logs. |

The first cleanup test attempted a read from a destroyed native buffer. The
native library aborted that isolated test process instead of returning a Python
exception. The corrected test records calls to the actual destruction methods
while retaining the allocated objects; it never submits a destroyed buffer.
The original C1 pre-compilation validation fixture also needed to initialize the
new lifecycle flag when constructing its device-free object with `object.__new__`.
Its original rejection and no-compilation assertions remain intact.

## Acceptance evidence

- Native SDK tests exercise custom melting/freezing, fractional energy, fuel
  conversion, material 255 movement, edit budgets, exact continuation, state
  aliases, incompatible restores, resource ownership, and failure atomicity.
- TypeScript properties compare Python catalog acceptance and SHA-256 hashes,
  protect registry inputs/outputs, exercise custom materials and immutable pass
  reports, and compare the native public API's complete state and every delta.
- `scripts/verify_sdk.py` builds real wheel/npm artifacts, installs them in a
  temporary directory outside the checkout, runs public clients, rejects leaked
  checkout imports or generator loading, compares state and 48 pass-delta reports,
  and checks declarations with both installed TypeScript compilers. Evidence and
  artifact hashes are in `c4-packages.json`.
- The standalone browser example exercises actual WebGPU and CPU instances with
  the same extension registry. Its verification includes per-pass deltas, exact
  replay, wrong-registry rejection, and rejection of concurrent state access.
  `c4-browser-native.json` matches the installed native client's initial/final
  snapshots and the SHA-256 digest of all 48 pass-delta reports. All 371217 Q units
  are conserved. The final package bundle hash matches the bundle actually tested
  in Chrome on the NVIDIA Lovelace adapter; source hashes also match.
- `c4-browser-ui-scene.json` verifies the actual 64x48 WebGPU example after the
  Step button advances 16 ticks: full state matches the CPU, total energy remains
  22906880 Q, and drift is exactly zero. `c4-browser-ui-restore.json` verifies that
  the Save/Restore buttons return both arrays and tick to their exact initial
  values. The browser console and page-error collections are empty after these
  checks. `c4-browser-ready.png` and `c4-browser-physics.png` show the initialized
  and evolved scenes; the earlier blank screenshot preserves the MIME defect.

The temporary browser and static server were closed after verification. C4 is
complete for the documented SDK contract and tested environment.

No arbitrary shader-plugin API, cross-device universal equivalence, pressure or
momentum solver, or performance improvement is claimed. Public GPU stepping reads
complete state back to the host; per-pass inspection adds further readbacks.
C5 must measure these costs and preserve the contracts while improving them.
C5-C7 remain unfinished.
