# C2: backend conformance

## Implementation and required behavior

- `engine/schedule.py` owns the pass schedule. Generated TypeScript/JavaScript
  definitions serve the CPU backend and WebGPU sandbox. Native GPU imports the
  same source schedule.
- `engine/cpu_physics.ts` implements every native pass, preserving immutable
  per-pass input, disjoint pair ownership, exact u32 hashing, thermal buoyancy,
  harmonic thermal exchange, phase priority, fuel/air matching, flame lifecycle,
  and transported kinetic/flag bits.
- Public CPU fields use this implementation and support exact packed snapshot
  restoration with absolute tick. The game-facing API remains usable.
- GPU diagnostics can capture each completed pass independently from full-tick
  snapshots. Conformance runs use those actual GPU results, not a second CPU oracle.

## Targeted sweep, findings, and prevention

| Finding | Validated evidence / fix | Prevention |
| --- | --- | --- |
| Two CPU fuels consumed one air cell. | A 3x1 wood-air-wood case now burns exactly one fuel. An in-memory mutant removing mutual ownership burns both, proving the property detects the old class. | Shared-oxygen positive property, CPU/GPU differential traces, mutation test. |
| CPU gas used density-only ascent and lacked sideways dispersal. | Hot smoke rises in the public field; mixed and baffled gas match native per-pass state. Removing physics work fails the gas-spread positive case. | Buoyancy/baffle cases, all-pass coverage, no-op negative control. |
| CPU movement had different ownership, eligibility, and scheduling. | Replaced in-place sequential decisions with immutable input and disjoint output pairs matching the native schedule; replay/resume matches. | SS009 input mutation lint, observer isolation, generated-schedule drift, SS010 copied-schedule lint. |
| JS multiplication cannot reproduce wrapped WGSL hash multiplication. | Math.imul matches native. An in-memory mutation to floating-point multiplication changes hash outputs on bounded coordinates. | SS008 TypeScript AST rule and hash mutation property. |
| CPU thermal/reaction rules discarded or rewrote different state. | Harmonic mean, signed truncation, kinetic/flag preservation, combustion pairing, ash/fire lifecycle, and phase priority now match native for complete packed words. | Per-pass whole-state equality using random thermal, kinetic, and flag fields. |
| Native reverse phase transitions evaluated an out-of-range local-array index. | For winner 0/1, winner-2u underflows before multiplication by zero. Replaced speculative access with an explicit lower-bound branch; native freeze/condense cases and every differential trace remain equal. | SS011 rejects unguarded subtractive local-array access, including multiply-by-zero/select pseudo-guards. |

The first SS011 version also flagged spatial storage indices guarded by coordinates.
It was narrowed to local arrays, where the lower-bound proof is explicit. Spatial
storage bounds remain covered by tiny, odd, and rectangular GPU scenarios; the
lint does not claim to prove arbitrary WGSL indexing safe.

## Validation matrix

24 scenes, 1,196 per-pass whole-grid comparisons, all 31 pipeline variants. Shapes:
1x1, 1x7, 7x1, 7x5, 8x8, 17x19. Three seeds per mixed shape, all four salts,
shared oxygen, hot smoke, orphan fire, baffled hot smoke/steam, isolated freezing,
and isolated condensation. Every mixed cell carries seeded thermal, signed kinetic,
and flag values. Public step/restore must match the final native state as well.

Deliberate code mutations execute in isolated in-memory modules; they never alter
the working tree. The complete verification report is `c2-verification.json`.
It must pass without source mutation before this checkpoint is marked complete.

## Limits retained for subsequent checkpoints

Conformance preserves the current native rules, including their known fidelity
limitations: fire/lava heat-source behavior, clamping, phase approximations, and
reaction energy choices. C3 must correct these with explicit accounting and
positive behavior, then update both backends and the version contract together.
No continuum-fluid, cross-device, or full state-space proof is implied.
